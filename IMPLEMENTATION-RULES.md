# Jordan Mercer Portfolio — Implementation Rules

## Design independence — high priority

This portfolio is produced by First Measure, but it must not look like the First Measure business website or like a recolored First Measure template.

Preserve the approved portfolio palette. Color changes are not the primary method of differentiation.

Treat the First Measure starter only as a technical foundation, never as a visual template. Do not carry forward its visual grammar merely because an existing pattern is convenient to reuse.

Avoid reproducing a First Measure-style composition through:

- repeated editorial section layouts;
- repeated bordered cards or panels;
- numbered section systems as a dominant motif;
- identical section-heading treatments throughout the page;
- repeated large editorial statement plus supporting-copy patterns;
- uniform section spacing that gives every section equal importance;
- repeated accent annotations as the primary visual device;
- the same grid/card structure for unrelated content; or
- a sequence of similarly constructed professional-content modules.

## Jordan's product-engineering identity

Jordan's portfolio should have a distinct product-engineering identity. The professional evidence itself should increasingly become the visual system:

- QueueFlow application and UI surfaces;
- architecture and system relationships;
- engineering decisions;
- code excerpts only where they are evidentiary;
- useful API and data structures;
- testing evidence;
- performance evidence; and
- technical metadata.

Integrate this material into the composition rather than placing it inside a generic collection of matching portfolio cards.

Each major area has a different visual job:

- **Hero:** concise professional introduction; never a First Measure-style hero.
- **QueueFlow:** dominant and immersive; it should feel like examining a software product and the engineering behind it, not another marketing section.
- **Experience:** compact career progression, not a card grid.
- **Engineering approach and capabilities:** describe Jordan's engineering system without becoming a résumé-style skill list or logo wall.
- **About:** quieter and simpler than evidence-heavy areas.
- **Résumé and contact:** a restrained conclusion.

QueueFlow must be unmistakably the centerpiece. Avoid stereotypical developer aesthetics: fake terminals, neon/cyber styling, decorative code, excessive dark-mode treatment, technology-logo walls, and generic SaaS landing-page patterns.

## Required originality check

Before a design revision is considered complete, answer this question:

> If the colors, candidate name, and copy were removed, would the page structure and composition still be readily distinguishable from the First Measure business site?

If the answer is no, the revision has not achieved sufficient design independence. Solve that through composition, hierarchy, evidence presentation, section grammar, grid behavior, typography treatment, and interaction patterns—not by changing colors.

Preserve approved content, evidence, positioning, and palette while creating a genuinely independent visual identity.
